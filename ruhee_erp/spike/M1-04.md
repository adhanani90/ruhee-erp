## Reproduce

M1-03's baseline must exist and `check_rate` must pass. From `~/frappe-bench`:

```bash
bench --site dev.localhost execute ruhee_erp.spike.posting_model.run
```

Each successful run adds eight invoices and a shift. It copies New Depo into its
own `M1-04 New Depo` profile, enables multi-currency/partial/credit sales, preserves
Sales Invoice mode and immediate stock updates, and disables background submit.
The dedicated profile's stock-availability block is off to use M1-03's negative
stock baseline. This is feasibility evidence with negative stock, not stocked-store
acceptance. All profile changes live in the script; existing differing settings
stop the run instead of being overwritten. It creates an invented cashier with a
random PIN, verifies it using the normal endpoint, locks the terminal and disables
that cashier on success. No PIN is logged. It never changes daily rates, item
prices, precision settings or submitted invoices. The original New Depo profile
and Claude Code's worktree/site are untouched.

Local validation: baseline rate check PASS; complete probe PASS, including
submitted document type, stock quantities, unchanged ledger snapshots at close,
invoice $50 balance and Accounts Receivable $50 balance assertions. Two preliminary
invocations failed during harness development (terminal locked, then incorrect
closing response unpacking); both were corrected without patching installed apps.
An earlier successful eight-bill run remains as invented local data; this evidence
is from the final run with report extraction and close snapshots.
